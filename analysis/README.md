# analysis/: evidence and verification

`verify_tables.py` recomputes the numbers reported in the manuscript and its
supplement from the files in this folder and compares each one with the value
printed in the paper, at the printed number of decimals. It ends with a
PASS / FAIL / SKIPPED summary and exits non-zero if any check fails.

```bash
python analysis/verify_tables.py                          # public evidence only
python analysis/verify_tables.py --private-evidence DIR   # adds the per-image WBCBench checks
python analysis/verify_tables.py --help
```

Default mode needs no WBCBench2026 per-image file. The opt-in mode reads per-image
WBCBench2026 predictions that you regenerate yourself (see
[Regenerating the WBCBench outputs](#regenerating-the-wbcbench-outputs)).

## What is checked

| Evidence (under `evidence/`) | Checks | Paper items |
|---|---|---|
| `backbone_common_manifold_internal/` | nine-class internal confusion matrices (12,803 held-out cells) of every Table 3 row and of the other Supp S7 pairs | Table 3 internal column; Section 3.3 ranking and spreads; Supp S4, S7 (internal scores), S17 (seven-class mapping) |
| `internal_ensemble/` | seven-class matrix and threshold sweep of the proposed model's internal three-seed ensemble | Section 3.8 internal recalls; Fig. 3 *n*; Supp S11 internal threshold and F1 |
| `lodo_proposed/`, `lodo/` | per-image predictions on the five public training sources, leave-one-dataset-out, seeds 42/52/62 (proposed recipe; earlier mixup/CutMix arm) | Table 1 pool sizes; Table 4; Section 3.5; Supp Note 1, S14, S15, S16 (proposed column) |
| `lodo_foundation/` | DinoBloom-B LODO grid, 30 summary rows | Supp S16; Section 3.4 |
| `leakage_audit/` | SHA-256 lists of the 1,260 TXL-PBC detector-training images and the 8,288 WBCBench2026 Phase-1 fields | Table 1; Section 2.2; Supp S1 |
| `frozen_probe/` | the frozen DinoBloom-B probe grid (`grid.csv.gz`: the `grid.csv` of `eval/frozen_probe.py`, 15 configurations) | Supp S7 |
| `wbcbench_confusion/` | WBCBench2026 counts only (no image ids): per-run 7x8 matrices, seed-ensemble matrices, McNemar counts, calibration bins, threshold sweep, field counts, ensemble agreement, re-evaluation change counts | Abstract; Tables 2 and 3; Sections 2.1, 2.8, 3.1-3.4, 3.6-3.9; Supp S1, S2, S6-S13, S17 |
| `../tables/` | the summary tables the supplement cites (S9, S10, S11, S12, Note 1) and the aggregate tables refreshed from the evidence | as cited |
| `MANIFEST.csv` | one row per run, withheld runs included; file hashes; no WBCBench-style identifier anywhere in the public files | archive integrity |

Every per-seed WBCBench metric in the paper (macro-F1, weighted F1, accuracy,
balanced accuracy, per-class F1 and recall, including the coverage-aware rows) is an
exact function of a 7x8 count matrix, so default mode reproduces all of them without
per-image data. The opt-in mode adds what needs the images one by one:

- it rebuilds every file of `wbcbench_confusion/` from the per-image predictions and
  compares it with the shipped copy;
- the image-level bootstraps: Supp S9 (2,000 replicates, `numpy.random.default_rng(0)`
  per model, `integers(0, n, n)`, percentile 2.5/97.5) and Supp S7 (5,000 paired
  replicates, `default_rng(12345)`, `choice(n, n, replace=True)`, images ordered by
  native class folder then file name, 95% and 90% percentile intervals, TOST at
  +/-0.02 on the 90% interval);
- the per-image change counts of the unified re-evaluation (Supp S17);
- the Supp S13 checks of the two hematologists' verdicts (each hematologist's counts by
  type, the cross-tabulation, the paired outcomes, the printed table rows and the shares
  in the main text), and that the reviewed cells, as a multiset of (type, benchmark label,
  model prediction), are the model's 205 panel cells; this needs the two verdict files and
  the proposed model's per-image runs in the private folder (the verdict files are not
  distributed).

Comparison rule: a value passes when the recomputed number, formatted to the decimals
the paper prints, equals the printed string; counts must match exactly. Supp S9 and
S11, and the main-text values quoted from them (Section 3.3: 0.865; Section 3.6: 0.719
and 0.839), cite 4-decimal table files as their source: those printed values pass when
their rounding interval overlaps that of the table value (the S11 BLAST oracle F1 is printed
0.849, the exact 982/1156 = 0.84948, which the table stores as 0.8495; S11 cites the
sweep counts for that cell), and the table files themselves are checked against the
recomputed values at 4 decimals (the S9 interval columns only with `--private-evidence`).

Author option: `--check-tex MAIN.tex SUPP.tex` confirms that every expected value
still occurs in the LaTeX sources as a whole value (not part of a longer, signed or
comma-grouped number),
including the values of checks skipped for want of private data. A short count can
also occur elsewhere in the sources, so this catches a value that disappears from the
paper but not every edit; Supp S13, a table of small counts, is therefore also compared
as whole printed rows.

## Layout

```
analysis/

  README.md
  evidence/
    MANIFEST.csv
    backbone_common_manifold_internal/   37 nine-class confusion matrices (.csv.gz)
    internal_ensemble/                   swin_proposed_confusion7, swin_proposed_threshold_sweep
    lodo/  lodo_proposed/                15 + 15 per-image files (public training sources;
                                         probabilities rounded to 5 decimals)
    lodo_foundation/                     grid_foundation_lodo.csv.gz
    leakage_audit/                       detector_train_image_hashes, external_field_image_hashes
    frozen_probe/                        grid.csv.gz
    wbcbench_confusion/                  run_confusion, ensemble_confusion, mcnemar_discordant,
                                         calibration_bins, threshold_sweep, field_counts,
                                         ensemble_agreement, reeval_changes (.csv.gz)
  tables/                                12 summary tables (.csv)
```

Directory names say what the runs are, not which table they feed; `MANIFEST.csv`'s
`paper_tables` column gives the current table and section numbers.

### Count files (`evidence/wbcbench_confusion/`)

| File | Columns |
|---|---|
| `run_confusion.csv.gz` | `run` (= `group/run_id` of MANIFEST), `true_label`, one count column per predicted class (`Basophil` ... `Promyelocyte`) and `__no_detection__`. Seven rows per run. `__no_detection__` counts labelled fields on which the detector returned no box; it is non-zero only for the full-pipeline route B and Phase-2 runs, whose coverage-aware metrics count those fields as errors (detected-cells-only view: drop that column) |
| `ensemble_confusion.csv.gz` | `ensemble`, `rule` (`probability`: mean of the seven-class probabilities over seeds, then argmax; `vote_tie42`/`62`/`82`: majority of the per-seed labels, a three-way tie taking that seed's label), `members`, `true_label`, seven count columns |
| `mcnemar_discordant.csv.gz` | `comparison`, `rule`, `model_a`, `model_b`, `n`, `both_correct`, `a_correct_b_wrong`, `a_wrong_b_correct`, `both_wrong` |
| `calibration_bins.csv.gz` | 15 equal-width confidence bins (lower edge exclusive): `n`, `n_correct`, `sum_confidence`, `sum_brier` of the proposed ensemble |
| `threshold_sweep.csv.gz` | one-versus-rest `tp`, `fp`, `fn`, `tn` of the proposed external ensemble for Blast group and Promyelocyte at thresholds 0.01-0.99 (positive when the class probability is at least the threshold) |
| `field_counts.csv.gz` | per split and native class: `n_fields`, `n_precropped` (Phase-1 crops at detector confidence 0.70), `n_detected` (full-pipeline detector at 0.30), with the seven-class label (empty: no counterpart) |
| `ensemble_agreement.csv.gz` | probability ensemble versus majority vote: disagreements and three-way ties |
| `reeval_changes.csv.gz` | predictions changed by the 2026-09-30 unified re-evaluation, per run |

The internal matrices are `index = true class, columns = predicted class` over the
nine internal classes. LODO files are the LODO evaluator's `predictions.csv`
(`eval/run_lodo_eval.sh`) reduced to `image_id` (the file name; `class/file` for HRLS,
whose file names repeat across class folders), `true_label`, `pred_label` and the nine
`prob_*` columns rounded to 5 decimals. `pred_label` is the nine-class argmax of the
unrounded probabilities and is what every per-seed number uses; rounding leaves a
top-two tie in two of the 771,768 rows of the 30 files (both BMCMHF), so take
`pred_label` rather than re-deriving the argmax.

### `MANIFEST.csv`

One row per run, including the runs whose per-image files are withheld. Columns:
`group, run_id, paper_tables, model, recipe, seed, route, eval_set, protocol, n_eval,
has_probabilities, macro_f1, weighted_f1, accuracy, balanced_accuracy,
detected_fraction` (metrics of the run's own file: seven-class for WBCBench runs,
present-class for LODO runs, nine-class for internal matrices), then

- `release`: `public` (the evidence is in this repository) or `withheld_wbcbench`
  (WBCBench2026 per-image material, not distributed);
- `wbcbench_derived`: `no`, `per_image`, `hash_only` or `aggregate`;
- `status`: `current` or `superseded` (kept because the paper quotes them: the
  original-corpus CNN runs, Methods; the pre-unified route and Phase-2 runs, Supp S17);
- `file`, `sha256`: the public file that holds the row's evidence and its SHA-256;
- `withheld_file`: where the withheld per-image file sits in a private evidence folder
  (path relative to its `analysis/evidence/`);
- `regenerate`: the shell command that recreates the row with this repository's
  `eval/`, `pipeline/`, `train/` and `data_prep/` scripts, run from the repository root
  with the variables of [Regenerating the WBCBench outputs](#regenerating-the-wbcbench-outputs)
  set; text after `#` is a comment. When the weights are not released, the command
  starts with the `train/scripts/` runner that retrains the model and `note` says so.
  Rows that no script recreates (superseded runs, the hematologist review, the
  per-field label lists) say so in words instead;
- `note`: provenance and caveats of the row.

## Regenerating the WBCBench outputs

1. Download the WBCBench2026 competition release used in the paper (Phase-1: 8,288
   fields; Phase-2 evaluation split: 5,350 fields) and build the class folders with
   `data_prep/prepare_wbcbench.py` (see `data_prep/README.md`). The commands in
   `MANIFEST.csv` refer to them as `$WBCB_P1_FIELDS` and `$WBCB_P2_FIELDS` (full
   fields, one folder per native class) and `$WBCB_P1_CROPS` (the pre-cropped set: the
   detector's highest-confidence box per field at confidence 0.70). They also use
   `$DATA_ROOT` (the prepared data of `data_prep/`: the nine-class corpus
   `Mixed_data_mix_mono_9_split_copy`, the LODO folds, `TXL-PBC/`) and `$ROUTE_C_DIR`,
   `$ROUTE_D_DIR` (the Cellpose crops of routes C and D, the variables and defaults of
   `eval/run_routes_ablation.sh`). Set `OUT_ROOT` to a folder outside the repository.
2. Put the 13 core weight files in `models/` (`yolo11_wbc_detection_best.pt`,
   `swin_base_colour_aug_cwce_seed{42,62,82}.pth` and the BPaCo package
   `swin_base_bpaco_seed*.pth`, `resnet50_bpaco_adamw_seed*.pth`,
   `resnet50_bpaco_sgd_seed*.pth`). Rows whose weights are not released say so in
   `note`; their `regenerate` command retrains the model with its `train/scripts/`
   runner first (run folders under `$OUT_ROOT`, as in `train/README.md`).
3. Run the `regenerate` command of each row, or the runners in `eval/`:
   `run_augmentation_recipe_eval.sh` and `run_backbone_external_eval.sh` (pre-cropped
   runs, `eval/evaluate_classifier.py`), `run_dinobloom_external_eval.sh`
   (`eval/evaluate_dinobloom.py`), `run_resolution_scaling_eval.sh`
   (`eval/evaluate_resolution.py`), `run_routes_ablation.sh` (no localization and routes
   B-E: `pipeline/detect_yolo11.py`, `data_prep/cellpose_crop.py`, then
   `eval/evaluate_classifier.py`), `run_full_pipeline_eval.sh` (Phase-1 and Phase-2
   full pipeline), `run_internal_mapped_eval.sh` and `run_lodo_eval.sh`. External
   evaluation uses horizontal-flip test-time augmentation.
4. Lay the outputs out as `DIR/<group>/<run_id>.csv` (or `.csv.gz`), with `group` and
   `run_id` from `MANIFEST.csv`: the evaluator's `predictions.csv` (or its
   `--dump-preds` file) for a run, the detector's `detections.csv` for
   `detections/phase1_seed62_detections` and `detections/phase2_seed{42,62,82}_detections`,
   and the evaluator's `predictions.csv` of the proposed model, seed `S`, also as
   `DIR/predictions/proposed_swin_seed{S}_wbcbench_phase1.csv` if you want the
   calibration and threshold files rebuilt. The bootstrap of Supp S7 and the field
   counts also need `DIR/wbcbench_labels/phase1_raw_labels.csv`
   (`image_id, raw_label, label7, in_precropped`) and `phase2_raw_labels.csv`
   (`image_id, raw_label, label7`). No script in this repository writes them: the
   authors listed the class folders of step 1 (`$WBCB_P1_FIELDS`, `$WBCB_P2_FIELDS`),
   one row per field sorted by `image_id`, with the file name as `image_id`, its native
   class folder as `raw_label`, the seven-class label of that folder (`GT7` in
   `verify_tables.py`; empty for classes without a counterpart) as `label7` and, for
   Phase-1, whether the file is also in `$WBCB_P1_CROPS` as `in_precropped`. Build
   them the same way from your copy; without them those checks are SKIPPED.
5. `python analysis/verify_tables.py --private-evidence DIR` (add
   `--dump-counts OUT` to write the rebuilt count files). Checks whose inputs are
   missing are reported as SKIPPED.

GPU nondeterminism and library versions can change a few predictions; the rebuild
checks then name the count files that differ, and values within rounding of the
printed ones still pass. A different release of the benchmark (other labels or
images) will not reproduce the counts.

## Conventions

- Seed summaries are the mean and population SD (ddof = 0) over the seeds of a row.
- External metrics are on the seven evaluation classes. Each seed's nine-class
  argmax is mapped to seven classes (`pred_label`); probability ensembles sum the
  nine-class probabilities into seven classes, average over seeds and take the argmax.
  Archived probabilities carry five decimals; this changes no reported value.
- Coverage-aware rows (route B on Phase-1, Phase-2) append each labelled field
  without a detection as a prediction that matches no class; it is not averaged as an
  eighth class.
- Balanced accuracy is the mean recall over the classes present in the true labels;
  LODO macro-F1 is over the classes present in the held-out source (Supp Note 1 gives
  the fixed nine-class and the union-of-labels variants, both checked).
- The LODO per-image files contain predictions on public datasets; the Raabin-WBC
  rows follow that dataset's own terms of use.
