# Paper map

For every table and figure of the paper, and for the results reported only in the text,
this map lists the scripts in this repository that produce it, their inputs, the expected
values, the public evidence from which `analysis/verify_tables.py` checks them, and
whether the released weights are enough to regenerate them.

Line numbers refer to the LaTeX sources of the manuscript (`main`) and the supplementary
material (`supp`) as of 2026-11-21; each value is printed on the line or within the range given.

Columns:

- **Produced by**: scripts in this repository, in the order they run. Runner settings in
  parentheses are environment variables or positional arguments of that runner.
- **Inputs**: data folders built by `data_prep/` and the weights. *P1 crops* =
  `$WBCB_P1_CROPS` (pre-cropped WBCBench2026 Phase-1 set, 8,061 cells evaluated);
  *P1 fields* = `$WBCB_P1_FIELDS` and *P2 fields* = `$WBCB_P2_FIELDS` (full fields, one
  folder per native class); *internal test split* = `test/` of the merged corpus
  (12,803 cells); *LODO data* = the leave-one-dataset-out folds and held-out pools.
- **Expected**: values as printed in the paper.
- **Checked from**: files under `analysis/` from which `python analysis/verify_tables.py`
  recomputes the printed values in its default mode. *private* marks checks that run only
  with `--private-evidence` (per-image WBCBench2026 outputs that you regenerate; for Table S13,
  the authors' withheld verdict files).
- **Released weights**: *Yes* if the 13 files of the weights record suffice (see
  `README.md`); *No* if the record alone does not regenerate the value, for the reason the
  cell gives: the models are not in the record and must be retrained with `train/scripts/`
  (or the value is the training run itself), the value needs the authors' exact internal
  split (note 3), or the earlier evaluation paths are not part of this repository. Other
  values: *refitted* (the frozen probe, which `eval/frozen_probe.py` refits from the public
  DinoBloom-B weights), *no weights needed* (the label mapping, Fig. S1) and *withheld* (the
  hematologists' verdicts, which no weights reproduce).

## Notes

1. **Detector validation (main 365-367).** `python train/train_detector.py --data /path/to/TXL-PBC/data.yaml --dry-run`
   writes a WBC-only copy of TXL-PBC (symbolic links plus filtered labels) to
   `$OUT_ROOT/detector/yolo11m_txlpbc_wbc_only_s512_dataset/` without training; its
   validation split has 252 images with 257 WBC boxes. Validate the released detector on
   it with Ultralytics 8.4.82 (`journal_env`):

   ```bash
   python -c "import os; from ultralytics import YOLO; YOLO('models/yolo11_wbc_detection_best.pt').val(data='$OUT_ROOT/detector/yolo11m_txlpbc_wbc_only_s512_dataset/data.yaml', imgsz=512, project=os.path.abspath('$OUT_ROOT/detector'), name='val_released')"
   ```

   `project` and `name` put the validation plots in `$OUT_ROOT/detector/val_released`.
   Without them Ultralytics writes to the runs folder of its own settings (`runs_dir`),
   outside `$OUT_ROOT`, and it also puts a relative `project` under that folder, hence the
   absolute path. A CPU run of this command reproduced the printed precision, recall and
   mAP@50; its mAP@50-95 differed from the printed value in the third decimal, because
   detector numerics differ slightly between devices.
2. **Detector thresholds of the training-source crops.** The per-source pools behind Table 1,
   Table S1, Table S15 and the leave-one-dataset-out folds were cropped at 0.30 for AML-LMU,
   PBC, Raabin-WBC and HRLS and at 0.70 for BMCMHF (Section S1 and the Table S1 and S15
   captions: supp 54-57, 67-68, 964-965; the main text calls them source-specific, main
   288); the merged internal corpus and the pre-cropped WBCBench2026 set used 0.70 (main
   268, 288; supp 56, 98-99, 116-117). `data_prep/crop_training_sources.sh` reproduces
   the pools as run; `data_prep/README.md` ("Detector thresholds as run") gives the
   evidence.
3. **Internal-test results.** Table 3's internal column, Table S4, the internal scores of
   Section S7, the internal seven-class values of Section S17, the internal panel of Fig. 3,
   the internal thresholds of Table S11 and the internal values quoted in Sections 3.3, 3.4,
   3.5 and 3.8 are computed on the authors' 12,803-cell test split of the merged corpus.
   The corpus can be rebuilt with the same class counts and split sizes, but not with the
   same cells in each split (`data_prep/README.md`), so most cells of a rebuilt test split
   were training cells of the released weights; evaluating the released weights on it is not
   a held-out test. Retrain on the rebuilt corpus for a fresh internal test, or check the
   printed values from the public internal confusion matrices. `eval/evaluate_internal.py`
   regenerates the eight trained rows of Table 3's internal column and Table S4 from their
   checkpoints without training (the released weights cover the proposed model and the three
   BPaCo rows; the CNN rows and fine-tuned DinoBloom-B must be retrained first), but
   only on the authors' exact split, whose membership list is not distributed
   (`data_prep/REPLAY.md`).
4. **Recipe-selection bootstraps (main 780-782).** `stats/recipe_ensembles.py` resamples
   images in the row order of its first input file. The printed intervals come from the
   unsorted file order of the original evaluation, which cannot be reproduced and is not
   distributed (it is a list of benchmark image IDs); `eval/evaluate_classifier.py` writes
   rows sorted by path, so regenerated intervals can differ slightly (`eval/README.md`; the
   order options are in `stats/README.md`).
5. **Withheld material.** The verdicts behind Table S13 and Section 3.9 are per-image
   hematologist verdicts on WBCBench2026 cells and are not part of this repository. The other per-image
   WBCBench2026 files behind the paper are withheld as well; `analysis/evidence/MANIFEST.csv`
   lists them (`release = withheld_wbcbench`) with the command that regenerates each from
   the released weights where possible.
6. **Reproducibility limits.** GPU inference is not bit-reproducible across hardware, and a
   detector re-run can move a box by a pixel or move a field across a threshold, so a few
   individual predictions can differ from the paper's runs. Retrained models reproduce the
   seed-level values closely, not exactly (`train/README.md`).
